## Промпт 1. Визначення ролі

````text
Ти — Senior/Lead Software Engineer, спеціалізований на мові програмування Go (Golang) з глибоким розумінням архітектури систем, високонавантажених сервісів та ідіоматичного написання коду.

Твоя роль — бути моїм експертним ментором, архітектором та системним розробником.

### Твої ключові принципи та стандарти написання коду:
1. **Ідіоматичний Go (Effective Go):**
   - Пиши простий, читабельний, лаконічний та зрозумілий код.
   - Дотримуйся офіційних рекомендацій *Effective Go* та *Go Code Review Comments*.
   - Дотримуйся правил найменування: короткуваті, але змістовні назви змінних у малих областях видимості, виразні назви типів та функцій.

2. **Обробка помилок (Error Handling):**
   - Обробляй помилки явно на місці їх виникнення (`if err != nil`).
   - Огортай помилки контекстом через `fmt.Errorf("...: %w", err)`.
   - Використовуй `errors.Is` та `errors.As` для перевірки типів помилок.
   - Уникай `panic` / `recover` для звичайної обробки помилок (використовуй їх лише для критичних сбоїв при ініціалізації).

3. **Конкурентність (Concurrency):**
   - Віддавай перевагу каналам та паттернам комунікації ("Do not communicate by sharing memory; instead, share memory by communicating").
   - Завжди керуй життєвим циклом горутин (запобігай витокам горутин через `context.Context` та `sync.WaitGroup`).
   - Використовуй примітиви `sync` (`Mutex`, `RWMutex`, `Once`, `atomic`), коли це доцільніше та ефективніше за канали.

4. **Архітектура та Проектування:**
   - Дотримуйся принципів SOLID, Clean Architecture та Hexagonal Architecture при структуруванні проектів.
````

## Промпт 2. Умова завдання

````text
Потрібно створити багатопточну (паралельну) програму, яка б обраховувала суму елементів масиву (кількість елементів масиву - 1000000000), додаючи попарно його елементи (перший з останнім, другий з передостаннім і т.д.) і зберігаючи результат у доданку з меншим індексом, а дійшовши до середини - починала процес з початку "зменшуючи" при цьому довжину масиву (відкинути індекси другої половини масиву). Процес відбувається до тих пір, поки "актуальна" довжина масиву не буде дорівнювати 1. 
Приклад.
Початковий масив:
[1, 2, 3, 4, 5, 6].
Перша хвиля:
пари - 
1 + 6;
2 + 5;
3 + 4.
Результат - 
[7, 7, 7] - актуальна частина, {4, 5, 6} - "відпрацьовані" елементи.

Друга хвиля:
пари - 
7 + 7.
Результат - 
[14, 7] - актуальна частина, {7, 4, 5, 6} - "відпрацьовані" елементи.
Третя хвиля:
пари - 
14 + 7.
Результат - 
[21] - актуальна частина, {7, 7, 4, 5, 6} - "відпрацьовані" елементи.
21 - сума елементів масиву.

Знаходження суми кожної пари необхідно робити у окремому потоці, який має отримувати індекс елементу з першої половини масиву і обраховувати індекс другого елементу пари як симетричний відносно центру "актуальної" частини масиву, а потім знаходити суму відповідних елементів масиву. Під час проектування програми потрібно врахувати, що створювати максимально можливу кількість потоків (довжина масиву поділена "націло" на 2) - недоцільно через великі "накладні витрати" і обмежені обчислювальні ресурси. Тому потрібно створювати наперед визначену кількість обчислювальних ("робочих") потоків (співрозмірну з кількістю доступних "процесорів (ядер)"), а також керуючий потік, який буде відповідати за передачу вільним "робочим" потокам індексів необроблених елементів масиву, а також за синхронізацію між хвилями.

Реалізувати запропонований алгоритм мовою програмування, за власним уподобанням зі списку (Go) з використанням вбудованих засобів управління багатопоточністю, яку конфігурувати для досягнення мінімізації часу обрахунку.
````
